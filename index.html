The data

Articles with no words in them

My Content wants to encourage reading by recommending relevant content. The MVP has one job: a reader asks, and five articles come back. With no data of its own yet, it learns from the public Globo.com news portal dataset.

The dataset is anonymised at the source. An article has no title and no text. It has an identifier, a category, a word count, a date and a vector of 250 numbers. There are no ratings either, only clicks, so every signal is implicit.

That shapes everything that follows. The system works without ever reading a word, and the interface can only show identifiers, a category, a length and a date.

What the service does

  • Takes a user_id and returns the n best articles, five by default.
  • Offers five strategies. The mixed one is served by default.
  • Serves a new reader from popular articles in their region, if known.
  • Never returns an empty list, whatever the request.
  • Keeps no state. For a reader it does not know, the caller sends the history with the request.

Collaborative ALS

Matrix factorisation built for implicit feedback, with the implicit library. Every empty cell counts as a weighted negative, which suits clicks better than ratings.

Strengths

  • Finds tastes that content similarity cannot see
  • Surprises, outside the theme already read

Costs

  • HitRate@5 of 0.0415 on the test period
  • Useless for a new reader or article
  • An article from two hours ago has almost no co-reads
  • Coupled, sensitive settings

Predicts ratings derived from clicks, with the Surprise library. Same algorithm three times, with three definitions of the rating.

Rating = article stars (log of clicks): 0.0015, does not rank. Binary with 1 sampled negative: 0.0080. Binary with 4 sampled negatives: 0.0815 on validation. The library and the algorithm are the same. The way the problem is posed changes everything.

Evaluation

The first numbers were wrong. The best one was a surprise.

The first score was 5.8 times too high

The first evaluation trained ALS on every click, then removed each reader's last click and asked the model to find it. The model had already seen that click. The score was 0.2415. Split by time instead, it is 0.0415.

0.0415

A factor of 5.8 of imaginary precision. Popularity does not benefit from the leak, because its ranking does not depend on the reader. The split is 60 / 20 / 20 by click time. Settings are tuned on validation and the test period is measured once.

The decision

Four slots to what is hot, one to what fits

The mixed strategy costs about 1% of precision and exposes 38 times more of the catalogue. It is the best measured compromise between being right and being varied.

The application

Pick a reader, get five articles

A Streamlit interface calls the Azure Function and shows the answer. It computes nothing itself. This is a real response from the deployed function.

GET /api/recommend?user_id=0&n=5&method=mix 200 OK · about 0.2 s warm { "user_id": 0, "method": "mix", "recommendations": [ 211442, 50644, 36162, 156279, 159938 ] }
  • Pick a readerFive articles come back with stars and reader counts.
  • Untick “recent articles”The list changes. This is the freshness effect, live.
  • Mark an article as readThe profile updates on demand, with no retraining.
  • Browse the catalogueWithout it, a reader would only click what the model already suggests.
  • Register a new readerRecommended immediately. Region is optional.
  • Publish a new articleAvailable within minutes. The saved PCA projection places it without refitting or recomputing the 364,047 existing vectors.

Two ways in, not one

The binding re-reads its blob on every call. That is exactly right for 23 KB that change every hour. Applied to 253 MB it would throw the cache away and pay for the download each time.

The service is stateless, since it keeps nothing between two requests. It is not memoryless, since the Recommender instance is reused and the 253 MB are read once per instance. At inference only numpy is needed. scikit-learn, implicit and Surprise run offline, to produce the artifacts.

What separates a service from a demo

None of these four failures raises an error. The service would answer 200 with bad recommendations. Each has a guard and a test.

Artifact driftCache validity is judged on the blob's size and date, so a rebuilt model of the same size is downloaded again.
Stale cacheThe container is enumerated at start-up, so artifacts added later are not missed.
Inconsistent catalogueAny identifier outside the catalogue is filtered out at load time and on every request.
Concurrent requestsThe history sent with a call lives in a threading.local and is cleared afterwards.

Industrialisation

Reproducible, and checked every time

87 unit testsThey run on synthetic artifacts, so no real data is needed.
Continuous integrationGitHub Actions runs tests, repository hygiene and Terraform validation on every push and pull request.
A deployed-service checkA script compares Azure's answer with a recorded reference. A service that answers is not a service that answers correctly.
Infrastructure in TerraformResource group, storage account and a Flex Consumption Function. The connection string is read from the resource, never written down.
One recommendation coreThe deployed copies are generated from src/recommender.py, and CI checks they are current.
